# 시연 시나리오 v0.1 (초안)

발표 슬라이드 4(입고 담당자 측정 화면)·5(포장 작업자 박스 지시 화면)를 중심으로, 팀 명세 02 §5의 호출 순서를 장면으로 옮긴 것. **상품 실물·장면 수는 미확정** — 데이터셋 선별 결과에 맞춰 채운다.

## 0. 사전 준비 (발표 전)

| 조작 | 확인 |
| --- | --- |
| `docker compose up` (백엔드·DB·프론트) | health 200, `docker compose ps`로 backend 기동 시각 확인 (구 컨테이너 응답 함정) |
| `POST /admin/demo/reset` | summary: 입고 풀 N / 출고 풀 M / 대기 배치 K / 토트 10/10 / 박스 각 100 |
| `GET /admin/demo/status` | 위와 일치, 접수 주문 0 |

## 1. 입고 — 신규 상품 등록 (슬라이드 4)

| 단계 | 화면·조작 | 데이터 |
| --- | --- | --- |
| 스캔 | 입고 화면에서 INBOUND 풀 상품 바코드 입력 → "신규" 판정, 1단 표시(마스터 이름·분류·이미지) | 입고 풀 상품 (치수 미확정) |
| 촬영 | '촬영' → 추론 결과(가로·세로·높이·신뢰도)와 저울 무게 표시 | **데이터셋 이미지 3장 → 추론 서버** (P1 접점 — 합의 필요), 무게는 사전 등록값 |
| 확정 | 게이트 통과 시 '승인' (미통과면 재촬영 or 수기) | 정답 치수와의 차이는 화면에 안 보임 — 질문 대비용으로 status에 정답 노출 여부는 미정 |
| 수량 입고 | 수량 입력 → 재고 반영 | 재고 0 → n |

반복 횟수: 1~2개 (선별 결과 중 "추론이 가장 잘 나온 것"부터).

## 2. 출고지시 도착

| 조작 | 화면 |
| --- | --- |
| `POST /admin/demo/orders/next` (배치 1: 합포장) | 라인별 배송단위 목록에 새 배송단위 등장(토트 번호 포함) |

또는 발표 중 손을 떼고 싶으면 `auto?intervalSeconds=N`으로 배치가 차례로 들어오게 한다.

## 3. 포장 — 박스 지시 (슬라이드 5)

| 단계 | 화면·조작 | 현황 |
| --- | --- | --- |
| 토트 스캔 | 토트 바코드 → 담을 품목·추천 박스·완충재 경고 | **P2 API 미구현** (토트 스캔→배송단위 상세). 현재는 라인별 목록만 가능 |
| 박스 오버라이드 | 필요 시 다른 박스 선택 | P2 |
| 포장완료 | 재고 차감·박스 재고 −1·토트 해제·처리량 +1 | P2 |

## 4. 이어지는 배치

`next` 2회: 배치 2(분할 — 배송단위 2개, 토트 2개), 배치 3(완충재 권유 표시). 각 배치가 화면 변화 하나씩.

## 5. 마무리

`GET /admin/demo/status` — 접수 주문·배송단위·토트 사용 현황을 요약 텍스트로. (관리자 대시보드 화면은 2차 MVP)

## 확정 필요

1. 입고 풀 상품 수와 어떤 상품인지 — 데이터셋 선별 결과
2. 출고 풀 구성 — 합포장·분할·완충재 장면이 나오는 치수 조합 (추출 후 레포 테스트가 검증)
3. P1 접점: 촬영 시 데모 테이블의 이미지·정답 치수 사용 (DM4)
4. P2: 토트 스캔→배송단위 상세 API 일정
5. 장면 3에서 "정답 치수 vs 추론" 비교를 보여줄지
