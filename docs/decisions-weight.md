# 편성에 무게 축을 넣은 결정 — 요약

대상: `feat/weight-cartonization`. 계약 정본은 docs 저장소이고, 이 문서는 backend 저장소 안의 결정 기록이다.
상세 명세는 [orders-import-spec.md](orders-import-spec.md) §4를 본다.

## 왜 바꿨나

기존 편성의 목적함수는 박스 개수 최소, 동점이면 총 부피 최소였다. 무게는 어디에도 없었다.
택배 요금은 세 변의 합 구간과 무게 구간 중 높은 쪽으로 정해지므로, 무게를 빼고 개수만 세면
부피가 남아도 무게가 구간을 올리는 편성을 최적이라고 낸다. 박스를 덜 쓰고 돈을 더 내는 셈이다.

## 결정

| # | 결정 | 반영 위치 |
| --- | --- | --- |
| 1 | 목적함수를 총 배송비 최소로 바꾼다. 동점이면 박스 개수, 그다음 총 부피 | `Cartonizer` |
| 2 | 배송단위 요금 = 요금 구간표에서 max(세변합 구간, 무게 구간) | `RateTable` |
| 3 | 요금 구간표는 기준정보 테이블 `shipping_rate_tier` | V13 |
| 4 | 세변합·최장변은 박스 외치수(내치수 + 판두께×2)로 잰다 | `CatalogBox` |
| 5 | 배송단위 총무게 = Σ 상품 무게 + 박스 자체 무게(`box_type.tare_weight_kg`) | `Cartonizer` |
| 6 | 하드 제약(세변합 160cm / 최장변 100cm / 총무게 20kg)을 넘으면 그 배송단위는 만들 수 없다 | `CarrierLimits` |
| 7 | 낱개 하나가 무게 한도를 넘으면 `OVERWEIGHT_ITEM` 거부 (2층) | `OrderScreener` |
| 8 | 포장완료 요청의 `measuredWeightKg`가 예상 총무게에서 허용 오차 밖이면 409 `WEIGHT_MISMATCH` | `ShipmentWeightEstimator` |

목적함수를 바꾸면서 국소 탐색이 **새 배송단위로의 이동**까지 보게 했다. 무게로 구간이 올라간
단위는 쪼개는 쪽이 쌀 수 있는데, 기존 단위 사이의 이동만으로는 단위 수가 늘지 않아 그 편성에
닿지 못한다. 채택 조건은 목적함수뿐이라 쪼개는 쪽이 비싸지면 그대로 기각된다.

## 근거가 없어 잠정으로 둔 값

전부 설정이나 컬럼으로 빼 두었다. 값이 들어오면 코드를 고치지 않는다.

| 값 | 현재 | 무엇을 확인해야 하는가 |
| --- | --- | --- |
| 요금 구간표 | 5구간 5000~9000원 | CJ대한통운 공식 페이지 접속 실패로 대조하지 못했다. 2026 최신표 재확인 |
| 판두께 | 0.5cm | 실제 쓰는 골판지 실측 |
| 박스 자체 무게 | 0.0kg | 박스 A~F호 실물 계량 |
| 무게 검수 허용 오차 | max(0.1kg, 예상×3%) | 저울 오차와 완충재 무게 |

요금표 출처: 파스토 2024 택배사 요금 비교 <https://guide-kr.fassto.ai/d4204e29-29fd-4e91-9b64-3784764a4fc2>,
CJ 공식 <https://www.cjlogistics.com/ko/utility/parcel-price> (접속 실패로 미대조),
우체국 30kg 구간 <https://smartpacker.kr/guide/postbox-size-guide/>.

## 기각한 안

- **적재 순서(무거운 것 아래) 규칙**: 상품별 내하중 데이터가 없어 규칙을 만들어도 검증할 수 없다. 편성은 무게 합만 보고 단위 안의 순서는 정하지 않는다. 눌림 위험은 기존대로 파손주의 플래그와 완충재가 담당한다
- **요금 미확정 구간을 0원으로 세기**: 요금을 모르는 구간을 선호하게 된다. 비교에서 가장 비싼 것으로 둔다
- **무게에 가중치를 두는 절충 목적함수**: 가중치를 정할 근거가 없다. 요금이 이미 무게와 치수를 한 수치로 합치므로 그것만 쓴다

## 한계

- 상품 무게(`product.weight_kg`)가 비어 있으면 편성은 0kg으로 보고, 출고 무게 검수는 건너뛴다. 편성 쪽은 요금이 실제보다 낮게 잡히는 방향이다
- 완충재 무게는 더하지 않는다. 실측값이 없다
- 요금은 동일권역 기준 하나뿐이다. 배송지역별 차등 요금은 넣지 않았다 — 주문의 배송지역은 지역코드 하나로 축약돼 있고(§2), 권역 구분과 매핑할 근거가 없다
