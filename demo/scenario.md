# 시연 시나리오 v1.0

발표 슬라이드 4(입고 담당자 측정 화면)·5(포장 작업자 박스 지시 화면)를 장면으로 옮긴 것.
상품·배치 구성은 `demo/data/products.json`·`orders.json` 이 정한 값 그대로다.

## 0. 사전 준비 (발표 전)

| 조작 | 확인 |
| --- | --- |
| `docker compose up -d` | health 200, `docker compose ps` 로 backend 기동 시각 확인 (구 컨테이너 응답 함정) |
| 열쇠 준비 | 시연 서버는 헬스체크를 뺀 모든 호출에 `X-Demo-Key` 헤더를 요구한다. 없으면 401 (D-26, demo/README.md 1장) |
| `POST /admin/demo/reset` | summary: 입고 풀 3 / 출고 풀 4 / 대기 배치 8 / 토트 40/40 / 박스 5종 각 100 |
| `GET /admin/demo/status` | 위와 일치, 접수 주문 0 |

추론은 Lambda `logistics-dimension-api:live` 를 부른다. `INFERENCE_LAMBDA_FUNCTION` 이 비어
있으면 서버가 mock 으로 기동해 치수가 호출마다 흔들린다 — 발표 전 이 값이 들어 있는지 본다.
리셋 끝에 추론을 한 번 깨우므로(`DEMO_WARMUP_INFERENCE`) 첫 촬영이 콜드 스타트로 8초를
넘기지 않는다.

## 1. 입고 — 신규 상품 등록 (슬라이드 4)

바코드는 화면 버튼이 `POST /admin/demo/inbound/next-barcode` 로 받아 스캔 칸을 채운다.
발표장에 스캐너가 없어서다. 순서는 GTIN 오름차순으로 고정이고, 리셋하면 처음부터 나온다.

| 회차 | 상품 | 실측 치수 | 추론 결과 | 화면 흐름 |
| --- | --- | --- | --- | --- |
| 1 | 농심 누들핏 카구리맛 40.5g | 10.0 / 9.9 / 9.9 | 3축 평균 오차 0.067cm, 종횡비 1.0 | 게이트 통과 → 승인 → 수량 입고 |
| 2 | 오리온 오뜨 치즈 12p | 25.2 / 31.6 / 3.9 | 25.1 / 31.5 / 4.1, 종횡비 7.7 | 게이트 통과 → 승인 → 수량 입고 |
| 3 | 하이트진로 테라 1600mL 페트 | 10.2 / 10.3 / 31.8 | 오차 0.033cm, 종횡비 3.1 | 게이트 통과 → 승인 → 수량 입고 |

각 회차 공통 순서 — 스캔("신규" 판정, 1단에 마스터 이름·분류·사진) → 촬영(S3 의
`images/{gtin}/cam1~3.jpg` 3장을 Lambda 로) → 치수·신뢰도와 저울 무게 표시 → 확정 →
수량 입력으로 재고 0 에서 n 으로.

무게는 사전 등록값이다(누들핏 0.064kg / 오뜨 치즈 0.392kg / 테라 1.662kg). 저울 연동은 없다.

세 회차 모두 게이트를 통과한다. 가장 납작한 오뜨 치즈가 종횡비 7.7 인데 임계값을 10.0 으로
두어(`inference.gate.max-aspect-ratio`) 추론이 조금 달라져도 승인이 막히지 않는다.
미통과·수기 확정 장면은 시연에 넣지 않는다 [확정].

신뢰도는 화면에 뜨지 않는다. 지금 Lambda 모델이 confidence 를 주지 않고, 게이트도 값이
없으면 신뢰도 항목을 건너뛴다(D-24).

정답 치수와 추론값의 비교는 화면에 띄우지 않는다 [확정] — 상품 선별 때 검토용으로만 썼다.

## 2. 출고지시 도착

`POST /admin/demo/orders/next` 를 누르면 대기 배치가 하나씩 접수된다. 주문은 전부 서울이라
배송단위가 모두 LINE A 에 붙는다 — 시연에서 라인은 한 곳만 본다.

발표 중 손을 떼려면 `auto?intervalSeconds=N` 으로 배치가 차례로 들어오게 둔다.

## 3. 포장 — 박스 지시 결과 (슬라이드 5)

바코드 스캔 모션은 흉내내지 않는다 [확정]. 접수가 끝난 배송단위의 결과 화면을 보여준다
(`GET /shipments/{id}` — 담을 품목·추천 박스·완충재 권유·배정 토트).

| 배치 | 담긴 것 | 결과 |
| --- | --- | --- |
| 1 | 고추참치 3 + 사골곰탕 1 | 배송단위 1개, C호 — 여러 품목 합포장 |
| 2 | 사골곰탕 10 + 국간장 6 | 배송단위 2개, E호·C호 — 한 박스에 안 들어가 분할 |
| 3 | 국간장 2 + 고추참치 2 | 배송단위 1개, C호 + 완충재 권유 |

배치 4~8 은 라인 대시보드를 채우는 몫이라 장면이 정해져 있지 않다.

포장완료 버튼을 누르면 재고 차감·박스 재고 −1·토트 해제·처리량 +1 이 일어난다.

## 4. 마무리

`GET /admin/demo/status` — 접수 주문·배송단위·토트 사용 현황이 요약 텍스트로 나온다.
관리자 대시보드 화면은 2차 MVP.
